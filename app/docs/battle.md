# Тактический бой (тестовая функция) — архитектура

Запрос автора (21.10.2026): поле 7×7, расстановка, свои ходы героев с реальными действиями, броски кубиков с физикой,
перебросы, навыки/эссенции в бою, ИИ монстров, экран наград с анимацией d10, местность и статусы.
Полностью отключается переключателем `state.settings.tactical` (по умолчанию ВКЛ; кнопка на главном экране и в меню мастера
лабиринта): тогда работает старый экран боя (`encounterOverlay` в index.html) и ни один файл боя не загружается.
Допущения по правилам, которых нет в `rules.md`, собраны в `../campaign/drafts.md` → «Тактический бой».

## Файлы (все в assets/, подхватываются сборкой и обновлением автоматически)

| Файл | Что внутри |
| --- | --- |
| `assets/css/battle.css` | все стили боя (`.bt-*` — поле и панель, `.bd-*` — окно броска) |
| `assets/js/battle-data.js` | `Battle.D`: местность, статусы+иконки, фоны зон, боевые таблицы 20 монстров 1 этажа, профили ИИ, перезарядки эссенций, типы урона |
| `assets/js/battle-core.js` | `Battle`: утилиты, модель боя, юниты, статусы, движение (Дейкстра), укрытия, свет |
| `assets/js/battle-rules.js` | атака, урон, спасброски, проверки, захват, толчок, смерть, реакции |
| `assets/js/battle-dice.js` | `Battle.Dice`: физика кубиков (canvas), окно броска, перебросы, спрайты и всплески атак, вращающиеся d10 |
| `assets/js/battle-act.js` | действия героя (`actionsFor`), перемещение, побег, предметы, расход времени хода |
| `assets/js/battle-ess.js` | эссенции 1 этажа: пассивки-хуки `Battle.P[id]` и активки `Battle.A[id]` (герои и монстры) |
| `assets/js/battle-ai.js` | ИИ монстров (и режим «Авто» для героев) |
| `assets/js/battle-ui.js` | поле, фон по зоне, местность, токены (ОЗ/мана/статусы), расстановка, эффекты, кнопка «Назад» |
| `assets/js/battle-menu.js` | панель действий героя, выбор целей/клеток, окна подтверждений, инспектор, меню боя |
| `assets/js/battle-end.js` | итог боя, экран наград, анимация d10, запас эссенций |

Загрузчик — `loadBattle()` в index.html (последовательно, по списку `BATTLE_FILES`; `BATTLE_REV` поднимать при изменении списка).
Классические скрипты делят глобальную область: боевые файлы видят `state`, `MONSTERS`, `ESSENCES`, `totals`, `derived`,
`giveParty` и т. д. напрямую. Любая ошибка боя → `ev.tactical = false` и открывается старый экран боя.

## Мост с приложением

- `startFight(ev)` ставит `ev.tactical = tacticalOn()`; `encounterOverlay()` при `ev.tactical` вызывает `Battle.ensure(ev)` и
  ничего не рисует (бой рисует свой слой `#battle`).
- Конец боя: `Battle.End.run` → `battleDone(ev, {outcome, killed})` → `finishFight()` (опыт, зачистка, журнал).
- Меню боя → «Обычный экран боя»: `Battle.abort()` закрывает поле, `ev.tactical = false`, убитые сохраняются в `ev.killed`.
- Мана героя `c.mp` (макс. `derived().mana` = 10 + 2 × уровень + бонус эссенций), восстанавливается на Отдыхе.
  Бонусы эссенций из строк `other` разбирает `essBonus(c)` (ОЗ, мана, КД, скорость).
- `c.insp` — «Вдохновение» (перебросы, выдаёт мастер), `c.dead` — погиб в бою (воскрешает мастер в меню героя).
- Запас эссенций отряда `state.inventory.essStash`; впитывание — меню героя → вкладка «Навыки» (слотов = уровень).
- Кнопка «Назад» телефона в бою: отменяет текущий шаг (✕ броска, выбор цели), иначе открывает меню боя.

## Поле и расстановка

7 × 7, клетка 1,5 м. `y = 0` сверху (монстры), `y = 6` снизу (герои). Зона героев — `y ∈ {4,5,6}` («первые три ряда»),
зона монстров — `y ∈ {0,1,2}`, `y = 3` нейтральная. Обычный бой: герои сами ставятся в свои 3 ряда (нажать героя, затем клетку),
затем приложение ставит монстров. Засада: герои стоят в ряд на 3-й линии (`y = 4`), монстры ближе (`y = 2–3`) и ходят первыми.
Расстояния — по Чебышёву (диагональ = 1 клетка). Большие существа занимают 2×2 (якорь — левый верхний угол).
Фон и местность зависят от зоны (`D.zones`): лагерь гоблинов, звериная чаща, погост, каменная пещера.
Препятствия (валуны, палатки, ящики, деревья, надгробия, кристаллы) не пройти и дают укрытие; кусты, туман — укрытие и скрытность;
грязь, кости, мох, колья — труднопроходимы; лужа — «Промок»; костёр — свет и огонь. В тёмных квадратах поле затемнено.

## Ход героя

Перемещение (скорость / 1,5 м клеток), действие, доп. действие, реакция. Панель героя: **Атака** (оружие, кулаки, метание, факел),
**Навыки** (активки эссенций + справка по пассивкам), **Движение** (подсветка досягаемых клеток, предпросмотр пути, ⚠ атаки по
возможности, подтверждение), **Оборона**, **Ещё** (Рывок, Отход, Помощь, Спрятаться, Захват, Толчок, Вырваться, Осмотреться),
**Предметы** (зелье, факел, удар щитом, ростовой щит, подобрать оружие, драконье сердце), **Побег**, **Конец хода**.
Выбор атаки подсвечивает радиус и допустимые цели; нажатие на цель открывает окно броска. До броска действие отменяется на любом
шаге (кнопка «Отмена», ✕ в окне броска, «Назад» телефона) и ничего не тратит.
«Два действия в свой ход» = действие + доп. действие (+ перемещение). Нажатие на любого бойца на поле открывает его карточку.

## Броски

Окно броска: заголовок, ✕ (отмена до броска), портреты атакующего и цели с оружием-спрайтом между ними, подсказки (модификаторы,
преимущество/помеха, КД/Сл), арена с кубиками, кнопка «Бросить» **или** бросок пальцем (зажать кубик — тянуть — отпустить: физика
с отскоками), серый значок переброса справа (оживает, если есть перебросы), «Далее ▸» / «ОК» внизу. Игрок бросает сам: атаки,
урон, спасброски героев (можно включить авто), проверки, спасброски от смерти. Броски монстров — автоматически с баннером.
После атаки на сцене: оружие летит к цели, на цели всплеск по типу урона (рубящий — росчерки, колющий/стрела — звезда, дробящий —
кольцо, огонь, холод, яд, молния, гром), число урона, затем «ОК».
Перебросы: «Наследие обряда» варвара (кости урона рукопашной атаки, раз в ход) и «Вдохновение» (`c.insp`).

## Конец боя

Экран итога: победа / монстры бежали / отряд отступил / поражение, опыт, камни (по 1 за убитого, класс камня = класс монстра),
затем один короткий бросок на эссенцию — два вращающихся d10 по очереди останавливаются; если выпало ≥ 95 из 100 хотя бы у
одного убитого, кубики светятся и показываются выпавшие эссенции (они идут в запас отряда). Все броски на эссенцию считаются
заранее, анимация одна независимо от числа убитых.

## Тесты

Скрипты Playwright лежат в `tools/battle-tests/` (описание и запуск — `tools/battle-tests/README.md`): `bsim.js` — массовые симуляции
боёв без UI с проверкой инвариантов, `bbal.js` — баланс, `brules.js` — частота попаданий против ожидаемой, `bui_*.js` — сценарии
интерфейса в Chromium (расстановка, ход, атака, отмена, бросок кнопкой и пальцем, переброс, все 20 навыков, реакции, смерть,
награды, «Назад», сенсорный ввод), `bui_monkey.js` — случайные действия героев через настоящий интерфейс. Общий прогон приложения —
`app_sweep.js` и `app_fuzz.js` — общий прогон приложения (бои в старом окне при `state.settings.tactical = false`).

Известная ловушка: меню лабиринта в `index.html` слушает клики по `[data-act]` на всём документе, поэтому кнопки боя помечены
`data-ba`. Не использовать в боевых файлах атрибуты `data-act`, `data-dg`, `data-inv`, `data-sup`, `data-guard`, `data-eat`.
